# LiveSpyer

Java 21 直播桌面客户端。支持 Bilibili 多房间观看、二维码登录和发送后断开的弹幕连接，也支持直接粘贴网页获得的 m3u8 地址。

## 播放引擎

当前使用 **Edge WebView2 + hls.js 1.5.15**，视频显示在 Java 软件窗口内，**不再依赖或加载 VLC**。

Java 负责房间解析、账号会话、网络请求、播放列表转发和界面。一个小型 Windows 窗口宿主负责将 WebView2 嵌入 Swing Canvas；该宿主不实现平台业务、不登录账号，也不打开直播间网页。hls.js 随应用分发，播放时不从外部脚本 CDN 加载。

当前浏览器播放器支持 **Windows x64、JDK 21、.NET Framework 4.8 和 Microsoft Edge WebView2 Runtime**。本机已安装 WebView2 并完成真实播放验证。其他系统尚未提供浏览器窗口宿主。

## 运行与分发

### Windows 11 图形化分发

执行 `./gradlew.bat packageWindows` 可生成包含 Eclipse Temurin JRE 21.0.12.1+1 和 WebView2 Fixed Runtime 153.0.4234.48 x64 的独立分发：

- `build/packaging/distributions/LiveSpyer-1.2.0.exe`：当前用户的图形安装程序，提供开始菜单和桌面快捷方式。
- `build/packaging/distributions/LiveSpyer-1.2.0-windows-x64-portable.zip`：完整解压后运行 `LiveSpyer/LiveSpyer.exe`，不要单独移动 EXE。
- `build/packaging/distributions/LiveSpyer-1.2.0-SHA256SUMS.txt`：两个分发文件的 SHA-256 校验值。

目标是 Windows 11 x64；不需要用户安装 Java、Gradle、VLC 或 WebView2。Windows 11 自带的 .NET Framework 4.8/4.8.1 用于窗口宿主，观看直播仍需网络。ARM64 设备尚未验证。包中保留 Java、WebView2 和各依赖的许可证；固定浏览器运行时需要随软件重新打包更新。安装包尚未做商业代码签名。

打包脚本固定并校验 JRE、WebView2 和 WiX 工具下载哈希；WiX 仅在构建时使用。构建机需要 JDK 21 和 Windows 自带的 .NET Framework 编译器。打包采用独立的宿主及依赖目录，避免覆盖正在运行的开发版播放器。

打包相关文件统一放在 `build/packaging/`：`distributions/` 为交付包，`app-1.2.0/` 为独立 EXE 目录，`libraries/`、`native-host/`、`input/` 为暂存文件，`downloads/` 与 `tools/` 为经校验的缓存。旧版本产物一并归入该目录。根目录 `packaging/` 仅保存需要版本管理的图标、许可证说明和使用文档，不存放生成的运行时或安装包；遗留 VLC 移至 `build/legacy/runtime/`，当前程序不使用它。

### 开发环境运行

Windows PowerShell：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
.\gradlew.bat run
```

首次构建会自动从 NuGet 下载固定版本的 WebView2 SDK（1.0.2903.40），校验 SHA-256，并使用 Windows 自带的 .NET Framework 编译器生成窗口宿主。无需安装 .NET SDK 或 VLC。SDK 和生成文件只放在忽略的 `build/` 内。

如通过 IDE 直接运行 `Main`，首次先执行：

```powershell
.\gradlew.bat buildBrowserHost
```

生成分发目录：

```powershell
.\gradlew.bat installDist
.\build\packaging\install\LiveSpyer\bin\LiveSpyer.bat
```

分发包含 Java 依赖、hls.js、浏览器窗口宿主、WebView2 SDK DLL 和相应许可证；不捆绑 JDK 或系统 WebView2 Runtime。宿主基于应用 JAR 的位置查找，不依赖终端当前目录。

若没有 WebView2，可从 [微软 WebView2 下载页面](https://developer.microsoft.com/microsoft-edge/webview2/) 安装 Evergreen Runtime。旧版的 VLC 便携目录可以保留，但当前程序不会使用它。

## 两种播放方式

### 粉蓝桌面界面

1.1.0 使用粉蓝主题、柔和渐变背景与半透明圆角卡片；主页提供添加直播间和粘贴链接的入口。观看页左侧为视频及控制区，右侧为可调宽度的实时消息面板；已检查 1280×850 和最小 1000×700 窗口布局。二维码与直链弹窗使用一致的配色和留白。

按钮悬停/按下过渡约 180 毫秒，只在交互时运行，按钮销毁时停止计时器，并遵循 Windows 减少动画设置。视频上的加载提示和播放按钮使用 `backdrop-filter` 实际模糊后方视频，浏览器减少动画偏好也被尊重。Swing 主背景为绘制的柔和色彩渐变、卡片为透明度混合，不宣称是系统桌面 Acrylic 模糊；不对整个视频窗口设置透明，以兼容原生嵌入画面。

布局和弹窗已做图像检查；实际 Bilibili 视频及游客弹幕已验证，扫码弹窗的视觉检查使用离线二维码，未登录账号或发送消息。

1.1.1 扩大默认窗口（在屏幕可用区域内最大为 1440×900），观看时自动收起品牌大标题、减少留白，并将扫码/退出登录保留在顶部“账号”菜单。点击“收起消息”扩大视频宽度，点击“专注观看”或双击视频隐藏顶部工具区、页脚和消息栏；恢复后保留之前的侧栏宽度。F11 进入全屏并自动专注观看；Esc 先退出全屏，或在窗口模式下退出专注。视频获得焦点时也通过本地消息桥接处理这些按键。

这些操作只改变布局，不重新取流、不关闭游客接收，也不裁切或拉伸视频比例。手动取消“显示弹幕与礼物”才会关闭接收连接。实际界面检查中，同一窗口的画布由 1088×535 扩大至专注模式的 1396×650；收起/展开、专注/还原和全屏切换保持相同播放器及游客订阅实例，关闭最后一个专注中的房间会恢复欢迎页。

**按房间号观看**

1. 选择哔哩哔哩，输入数字房间号或直播间 URL，点击“添加直播间”。
2. 可先扫码登录，也可尝试播放允许游客访问的公开直播流。
3. 每个标签页独立播放；切换标签不会停止其他房间。支持音量、静音、停止、全屏以及重新取流。
4. 登录后发送弹幕。收到服务端成功响应才清空输入，失败保留输入；保守限制为 20 个字符，同一账号两次请求至少间隔 3 秒。
5. 默认勾选“显示弹幕 / 礼物（游客）”，在视频上显示滚动消息，并在下方保留消息列表。显示平台提供的完整公开昵称、可用的荣耀等级，以及礼物名称和数量；礼物覆盖文字使用金色。关闭该选项会同时关闭游客连接和心跳；重新勾选可重新连接。

**直接播放 m3u8**

1. 点击“粘贴 m3u8”，粘贴完整 HTTP/HTTPS 地址，保留原有签名参数。
2. Bilibili 来源默认 Referer 为 `https://live.bilibili.com/`；其他来源可按实际需要修改或清空。
3. 点击确定后在独立标签页播放。支持音量、静音、停止和全屏。
4. 直链可能过期，届时需要重新复制。直链没有绑定直播间号，因此不提供二维码登录或弹幕发送操作，也无法自动重新解析原网站的播放地址。

当前直链转发仅使用必要的 Referer 和 User-Agent，不支持需要额外账号 Cookie 或 DRM 的媒体。

### 在线列表、已播时长与仅音频模式（1.2.0）

右侧在线列表默认折叠，仅显示前 3 名；点击“展开”查看接口提供的名单，最多 50 人，较小窗口使用滚动区域。当前使用 Bilibili 公开在线榜单（`getOnlineGoldRank`），展示平台返回的公开昵称及明确提供的荣耀等级。榜单人数和名单均来自该接口，不等于完整观众名册，也不会用房间热度冒充在线人数。昵称打码和榜单未列出的用户不做推测或还原。

已播时长根据 `Room/get_info` 返回的开播时间（中国标准时间）计算，每秒更新；房间信息与在线榜单每 30 秒匿名查询一次，与账号互动及游客弹幕连接独立。未开播、时间缺失和接口失败分别显示对应提示。暂停视频仍可查看房间信息，关闭房间取消查询和计时器。直链未绑定房间，不展示在线列表和主播时长。

勾选“无画面 · 仅音频流”只播放声音，仍可调节音量、静音和接收弹幕；取消勾选恢复视频。优先使用 HLS 声明的独立音频列表；对于当前 Bilibili 的未加密 fMP4/AAC 合流，通过严格校验的 HTTP Range 读取 MP4 元数据和音频采样区间，在 Java 内重封装音轨，跳过视频采样载荷。该方式仍需要少量封装元数据，并增加范围请求次数，不承诺更低延迟。

启用前检查实际音轨及 CDN 范围请求支持；不支持时提示失败并保留原模式，不回退下载完整视频。当前不支持从混合 TS、加密媒体或任意 MP4 封装提取纯音频；这些来源可提供独立音频 HLS 或继续普通播放。切换模式会短暂重新缓冲，保留音量、静音设置、浏览器宿主与游客订阅；“重新取流”保留选定模式，停止后切换选项不会自动播放。

已在房间 `1965473206` 验证公开名单与开播时间，以及真实 WebView2 视频 → 仅音频持续播放 → 恢复画面。单次现场音轨分片约 30 KB、范围读取及重封装约 0.6 秒，此数值随流与网络变化。离线测试检查音频范围不覆盖视频载荷、拒绝忽略 Range 的服务端、失败保留原模式、信息查询关闭取消及超 24 小时时长。声音听感与干净 Windows 11 虚拟机安装仍需人工验证。

## 播放与互动相互独立

```text
房间号 → 解析 HLS 地址 ─┐
粘贴 m3u8 ────────────┴→ Java 本地媒体转发 → hls.js → WebView2 视频画面

房间弹幕发送：
disconnected → connecting → 服务端鉴权成功 → connected
             → HTTP 提交弹幕 → 成功或失败均关闭连接 → disconnected
```

播放器只加载本地播放页面，不加载 Bilibili 直播间网页，不建立弹幕 WebSocket，不运行房间互动心跳。账号凭据仅保存在 Java 内存中，不传入浏览器或 CDN。退出登录清除本地会话，已经取得的媒体地址继续播放。

`disconnected` 表示本客户端互动连接已关闭。平台在线名单、入场事件和缓存由服务端决定，关闭连接不保证账号立即从名单消失，也不撤销已产生的记录。带签名的媒体 URL 不等于匿名访问。

直链标签和房间标签都通过随机令牌保护的 127.0.0.1 端口获取媒体。Java 转发层处理相对地址、主/子播放列表、初始化分片、密钥 URL、Range 和 LL-HLS 的重载参数，原样转发媒体字节，**不转码**。它不接受任意代理目标参数，不将账号 Cookie 转发到媒体源，也不允许浏览器导航到直播间或其他网页。

### disconnected 时显示弹幕

账号的发送连接与游客接收连接是两个独立通道。游客订阅使用 `uid=0` 和平台签发的匿名设备标识，通过签名接口获得游客连接令牌；它不接收账号会话参数，也不携带 SESSDATA、bili_jct 或登录 UID。账号仍可保持 disconnected，直到用户需要发送弹幕。

实时接收必须保留一个游客 WebSocket，并每 25 秒发送接收连接的心跳。平台可能把它计为游客在线，不能保证完全不留下访问记录。取消“显示弹幕 / 礼物（游客）”或关闭房间，会停止接收和心跳。暂时停止视频或退出账号登录不会自动关闭已勾选的游客弹幕。

游客连接断开后最多退避重连 3 次，失败后显示状态并等待重新勾选，不会回退到使用账号登录。支持普通、zlib 和 Brotli 弹幕包；对帧大小、解压大小、嵌套、队列和历史记录均设上限，避免高流量房间阻塞界面。弹幕使用纯文本渲染。

昵称优先使用消息中用户信息的公开 `base.name`，缺失时使用基础昵称；不主动截断有效昵称，不使用神秘人 `origin_info` 恢复原身份。服务端若仅提供打码名称，无法保证显示全名。荣耀等级读取 `user.wealth.level` 或 `info[16][0]`，与粉丝牌等级、用户等级和舰长等级分开；缺失或为 0 时不显示荣耀标签。

在房间 `1965473206` 的游客只读检查中，未点击“回到直播”就收到基础昵称、`base.name` 和 `origin_info.name` 同时打码、UID 为 0 的消息。客户端遇到这种数据会提示“收到平台打码昵称”；不能用 UID=0 或首字缓存匹配全名，否则可能把不同观众串成同一人。“回到直播”只调整视频播放位置，不修改昵称，也不重建游客订阅；首次出现全名不保证后续消息仍包含全名。

该房间的 75 秒独立游客检查收到 4 条打码弹幕及平台 `LOG_IN_NOTICE`；另一次实际界面检查点击“回到直播”后订阅对象保持不变，后续星号消息触发了上述提示。尚未确定服务端何时切换昵称下发策略，也未复现完整昵称被按钮本身改成星号的情况。

“自动刷新弹幕会话”默认开启：每次游客鉴权成功后约 15 秒刷新；收到打码弹幕时立即唤醒后台任务刷新，不等周期结束。旧游客 WebSocket 关闭后，重新取得匿名设备标识及令牌，再建立游客连接；同一时刻只允许一次刷新。无消息时也按周期刷新，但不将其计为恢复成功或失败。视频和账号发送连接不参与刷新。关闭选项可停止后续自动刷新；关闭弹幕或房间会取消正在进行的刷新。刷新涉及网络请求，完成仍需耗时，期间可能漏收消息，不回放或重发弹幕。

若重建后的会话连续 3 次仍只有打码弹幕，自动刷新暂停，现有游客连接继续接收；关闭后重新开启该选项可再次尝试。缺少弹幕的会话不会被判为恢复成功，礼物全名也不作为弹幕恢复全名的证据。平台仍可能立即打码，不能保证重置会话有效；原有网络异常重连独立限制为最多 3 次。

礼物支持 `SEND_GIFT` JSON 和 `SEND_GIFT_V2` Protobuf 批量消息（使用固定版本 protobuf-java 4.33.5）。显示赠送者、礼物名称及本次数量；连击汇总 `COMBO_SEND` 不重复显示。新版礼物尚无已核实的荣耀等级字段，因此不会猜测等级。礼物为文字提示，尚不包含动画特效、上舰或醒目留言等其他事件。视频与列表都按纯文本显示昵称和消息；高流量时沿用有界队列和覆盖层限流，并非完整礼物账本。

只有绑定了房间号的标签才能订阅弹幕；纯 m3u8 直链无法确定对应房间。实时弹幕按接收时间显示，不会自动与存在延迟的视频画面严格对齐。

关闭标签会停止媒体转发、结束该标签的浏览器宿主，并尝试清理其独立临时浏览器目录。该目录不复用用户的 Edge 登录资料。

## 低延迟策略

- 优先选择 H.264 fMP4 HLS，无兼容流时回退 TS。分片时长由平台决定。
- hls.js 启用 `lowLatencyMode`，目标同步距离为 1 个分片，超过 3 个分片的距离时追赶；允许最高 1.1 倍速追赶。
- 前向缓冲目标 4 秒、最大 8 秒，已播历史缓冲不保留。前向缓冲上限不等于额外延迟。
- 去掉了旧 VLC 自适应流模块的内部缓冲限制，但普通 HLS 仍受完整分片发布时间、CDN 和网络影响，不能承诺总延迟低于 300ms。
- 平台实际提供 LL-HLS 的部分分片时，播放器与转发层保留相应能力；普通 m3u8 不会因打开低延迟开关自动变成 LL-HLS。
- 较激进的同步距离更容易受网络抖动影响。播放错误最多自动重试两次，之后手动重新取流或重新粘贴地址。弹幕发送不自动重试。

### 为什么仍可能比网页慢

同为 m3u8 不代表使用相同播放列表、CDN、清晰度或分片发布时间。即使地址完全相同，网页的起播位置、卡顿后的追赶策略也可能不同。本客户端按约一个分片的同步距离播放，还经过 Java 本地转发；普通 HLS 的整片等待并不会因使用浏览器内核消失。尚未拿用户当前网页的实际地址和时间戳做同步对照，不能将剩余差异全部归因于某一个因素。

播放状态现在显示“距流边缘约 X 秒”，取自 hls.js 对播放列表直播边缘的估计。这不是端到端延迟，也不是与网页的延迟差。点击“回到直播”会跳到 hls.js 当前的同步位置，无需重新登录或重建账号互动连接；它无法消除源头编码、分片发布和 CDN 的延迟。

## 扩展接口

| 接口/类 | 职责 |
| --- | --- |
| `LivePlatform` | 平台标识、房间解析、取流、登录及互动连接工厂 |

| `RoomInteraction` | 等待鉴权的 connect、发送及幂等 close |

```text
META-INF/services/top.vrilhyc.applications.platform.LivePlatform
```

ServiceLoader 实现需要公开无参构造函数和唯一平台 ID。取流不得创建常驻互动连接；connect 返回前须收到鉴权成功；close 必须幂等并处理连接中的取消；网络调用应有超时；日志不得包含 Cookie、Token 或完整带签名 URL。
